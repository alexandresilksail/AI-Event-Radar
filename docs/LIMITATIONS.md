# 已知限制与后续扩展

## 依赖外部条件才能启用（框架已就绪，绝不伪装已实现）

1. **AI 结构化抽取**：需配置 OpenAI 兼容 `AI_BASE_URL/AI_API_KEY/AI_MODEL`。
   未配置时使用规则抽取（日期/城市/类型/免费判定），字段缺失填「待核实」。
2. **搜索引擎全网发现**：需配置 `SEARCH_PROVIDER`（serper/tavily/bing）+ Key。
   发现结果进入候选源队列（status=candidate），管理员审核后才纳入长期监控。
3. **邮件/Telegram/企业微信通知**：需在通知规则中配置对应凭证；
   未配置时记录 skipped_no_credentials，平台其余功能不受影响。
4. **Eventbrite/Meetup 等平台深度接入**：APICollector 框架可直接配置其官方 API；
   需要平台账号与 API Key，且遵守各平台配额。
5. **微信公众号**：受访问控制，不做批量抓取；支持人工提交单条 URL 收录。

## 已知限制

- 去重相似度为 SequenceMatcher 字面相似度 + 规则加权；语义级去重预留 LLM 钩子
  （配置 AI 后可增强），当前以「合并不删除 + 保留全部来源」策略兜底误判。
- 「已延期/已取消」目前依赖重新采集时的信息更新与时间判定（自动判结束已实现）；
  主办方主动公告的取消信息需重新抓到原文才能变更状态。
- 活动结束状态按时间自动判定，统计中的「取消率」仅统计被明确标记为 cancelled 的活动。
- 24 小时稳定性验收需真实运行 24 小时后方可宣称通过（方案见 ACCEPTANCE.md）。

## 后续扩展方向

- Alembic 正式迁移链；Celery + Redis 分布式队列（当前 APScheduler 单机版满足个人运营规模）。
- 日/韩/德/法/西语抽取规则扩展（当前中英优先，模型抽取天然支持多语言）。
- 活动页自动识别报名表单/ICS 日历下载。
- 前端国际化（i18n）与 shadcn/ui 组件库升级。
